One row = one obstacle crossing (participant x obstacle x repeat) or one level walk (`is_level` = 1). Both limbs are in the row, named by role (`lead_`, `trail_`). Empty cell = not computed (never imputed).

## Roles

- **ID** identifiers · **LABEL** encodes the obstacle (never a feature: leakage) · **META** design/participant/event info · **FEATURE** wearable (Dot) inputs · **FLAG** quality/inclusion · **REFERENCE / TARGET** camera values (never features).

## Definitions confirmed against the existing code

- **Stride** = ZVP -> ZVP (mid-stance -> mid-stance) of one foot, from the Dot foot IMU (step 4; saved, hand-edited ZVPs). **Swing** = the step-4 toe-off (inverted foot-roll minimum) -> heel-strike (foot-roll maximum) inside that stride; all `% swing` values use that window (0 = toe-off, 100 = heel-strike).
- **Segment sign** (Dot thigh/shank/foot euler X): sign-normalized per participant x side with step 9's templates (`signTemplates.mat`, level-walk shape correlation + polarity anchor: thigh forward-tilt dominant positive, shank heel-up dominant negative, foot toe-down dominant negative). So max = thigh forward / shank forward / foot toe-up and min = thigh backward / shank backward (heel-up) / foot toe-down. The thigh and shank anchors are a physiological convention (the camera has no thigh/shank markers); the foot sign is checked against the camera foot pitch in build_report.md.
- **Offset correction**: `_corr` = value - the angle at the same stride's begin-ZVP (median of the first 4 of 200 normalized samples; step 9's peak-excursion reference). Raw `_max`/`_min` are not offset-corrected.
- **Camera frame** (WorldViz PPT, refined CV trajectory): y = walkway, obstacle centre at y = 0, z = height; marker centres (no sole offset; obstacle top = marker - 20 mm). Clearance = foot z over the obstacle - obstacle top. Take-off = near edge - own TOE y at begin-ZVP; landing = own HEEL y at end-ZVP - far edge (per limb, as step 8).
- **ZHC frame**: Dot global frame (gravity z-up, heading from the Dot fusion), integrated per stride from that stride's begin-ZVP (origin), level-ground bias solve (end height forced to 0). Only the foot **sensor** position is integrated; the toe height (`*_zhc_peak_toe_h`, v2) is derived from it by a rigid-body transform with the Dot foot tilt.
- **Acceleration windows**: first / last 25% of the swing.
- **Level walks**: per level pass, the stride in which each toe crosses camera y = 0 (the obstacle location) moving +y, before the first labelled obstacle pass and outside every labelled one (the crossings file lists the level passes as unlabelled rows); both feet must be seen at y = 0; lead = the foot that crosses first; same swing window and features.
- **Sync**: Dot clock = camera clock + `dot_cam_sync_offset_s` (step 5, 3x left-leg raise).
- **Curves file** (`Crossing_Curves_YoungAdults.csv`): per row, each limb's swing curves at 0:2:100 % of its swing (thigh / shank / foot tilt, foot |acc|, ZHC height and progression). The Test 106 thigh gate also applies there: the thigh curve of a limb with a gated thigh value is empty.
- **Time-aligned file** (`Crossing_Aligned_YoungAdults.csv`): per row, both limbs' Dot signals at fixed samples around the TRAILING toe lift-off seen by the camera (`trail_toeoff_t_cam`; k = -90..36 samples at 60 Hz = -1.5 s to +0.6 s): thigh / shank / foot tilt (deg, same sign normalization), foot |acc| (m/s2, global frame, gravity removed) and foot height above the begin-ZVP of the stride that contains the sample (ZHC, mm; resets to 0 at every foot-flat). Columns `<role>_<signal>_s<m|p><k>`. Every sample with k < 0 is known before the trailing foot leaves the floor (real-time / cueing analyses). Same thigh gate; empty = outside the recording or no camera lift-off.

## Study-design notes (v2)

- **Roles and crossing strides are camera-derived.** `leading_limb`, every lead_/trail_ assignment and the stride chosen for each limb come from the camera crossings file (which foot passes y = 0 first, and the ZVP stride containing that instant). `role_imu` recovers the leading side from the Dot alone and `role_agree` / `imu_cross_stride_match` show how often it matches (build_report.md, task 5). An unseen-participant model that uses lead_/trail_ features therefore assumes the role and stride are known.
- **`height_cm` is the obstacle height used by step 8, not the nominal design height.** For 103-110 it is measured from the obstacle markers (marker centre - 20 mm); for 101-102 it is 10/20/30% of the typed leg length. It can differ from 10/20/30% of the leg length; the marker heights show a set-up change between Tests 104 and 105 (build_report.md, task 1).
- **Obstacles were run in blocks** of ~5 consecutive repeats (`order_randomized` should be "no"; `block_id`, `block_pos`), with a block order that differs between participants. Anticipation and within-block learning are possible; `trial_order`, `block_id` and `block_pos` are META and must never be features.
- **`lead_cam_takeoff_dist` is the own-foot definition** (lead toe at the lead limb's begin-ZVP, i.e. its stance before the trail foot's, a full step back), not the literature value. `lead_cam_takeoff_toeoff` / `trail_cam_takeoff_toeoff` give the toe distance before the near edge at the limb's own toe-off; the literature "trail foot placement" is `trail_cam_takeoff_dist`.
